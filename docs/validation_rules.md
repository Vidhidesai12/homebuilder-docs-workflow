# Stage 1 validation contract

The documents use Project 1's synthetic seed 42 naming convention, with no database connection. A known vendor is one of `Demo {Sitework|Concrete|Framing|Mechanical|Inspection} Vendor 01` through `08`. Communities are the eight `Demo` communities in Project 1's generator; lot numbers run from 1 to 150. Budget categories are `Sitework`, `Materials`, `Labor`, and `Permits`.

For this fixed fixture set, every document is dated November 2026. Project 1 has exactly one budget record per community and month; its November 2026 category is selected by `(month_offset + community_id) % 4`, where November 2026 has `month_offset=22`. No per-category budget rows are assumed. A document is a `budget_exception` when its amount exceeds **$25,000**, the Stage 1 document review threshold, and is assigned to that community-month's existing category. This threshold is a fixture policy, not an assertion about available funds in a live database. Stage 2 can replace it with a read-only lookup of the actual monthly planned and actual amounts and a defined approval policy.

An invoice is a `duplicate_invoice` if the same vendor and invoice number appeared in an earlier document in this fixture set. `unknown_vendor` means its vendor name is absent from Project 1's generated vendor pattern. The three exceptions are mutually exclusive and all other documents must have complete fields, valid community/lot/category, and arithmetically correct totals. The ground truth is an expected result for future validation code; Stage 1's n8n workflow extracts text only.
